🧭

Every FastAPI feature maps to an HTTP concept. Ten minutes on methods, JSON and status codes makes the rest of the day obvious.

What is an API?

🍽️ The restaurant analogy

You don't walk into the kitchen — you order from the menu and receive a defined dish. The kitchen (your model) can change recipes without customers noticing, as long as the menu (the API contract) stays the same.

An API (Application Programming Interface) is a contract: "send me a request in this format and I promise to answer in that format."

Client–server architecture: the server (our FastAPI app) listens on an address such as http://127.0.0.1:8000; clients (browser, curl, Python requests, a Java backend) send requests. They share only the contract — the client never needs scikit-learn installed.

Why is prediction a POST, not a GET?

Features are structured data that belong in a body, which GET requests should not carry. Inputs can be large or sensitive, and URLs end up in logs and browser history. POST + JSON body is the industry convention for inference endpoints.

Introduction to FastAPI

FastAPI is a modern Python web framework for building APIs. You write ordinary functions with type hints; FastAPI uses those hints to parse requests, validate data (via Pydantic), convert responses to JSON and generate interactive documentation — automatically.

Why FastAPI for ML model serving?

🛡️

Validation built in

Declare feature types and ranges once; bad input is rejected with a clear 422.

📖

Free docs

Swagger UI at /docs lets anyone try the model without code.

🐍

Pythonic

Same language as training — load the same joblib artifact and feature list.

🚀

Fast

ASGI-based; sync endpoints run in a thread pool so CPU-bound models don't block.

FastAPI vs Flask (high level)

Same endpoint, two frameworks — validate a non-negative integer tenure
from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()


class Input(BaseModel):
    tenure: int = Field(..., ge=0)


@app.post("/score")
def score(data: Input):
    return {"tenure": data.tenure}

Missing, non-integer or negative tenure → automatic 422 with a precise error, and the rule appears in /docs.

from flask import Flask, jsonify, request

app = Flask(__name__)


@app.post("/score")
def score():
    data = request.get_json(silent=True)
    if data is None or "tenure" not in data:
        return jsonify({"error": "tenure is required"}), 400
    try:
        tenure = int(data["tenure"])
    except (TypeError, ValueError):
        return jsonify({"error": "tenure must be an integer"}), 400
    if tenure < 0:
        return jsonify({"error": "tenure must be >= 0"}), 400
    return jsonify({"tenure": tenure})

Works perfectly — but every rule is manual code, and no documentation is generated.

What Uvicorn does

FastAPI defines what to do with a request; it does not open network sockets. Uvicorn is an ASGI server: it listens on a host and port, accepts HTTP connections, turns raw bytes into ASGI events, hands them to your app and writes the response back. 🍽️ Uvicorn is the waiter; FastAPI is the kitchen.

def greet(name: str):

@app.post("/echo")
def echo(payload: dict):
    return {"you_sent": payload, "number_of_keys": len(payload)}

Line by line

  • from fastapi import FastAPIImports the application class.
  • app = FastAPI(title=..., version=...)Creates the application instance. Uvicorn looks for this variable; title/version appear in the docs.
  • @app.get("/")A route decorator: "when GET arrives for /, call the function below".
  • def read_root(): return {...}The endpoint function. Returning a dict → JSON response with status 200.
  • @app.get("/health")A health endpoint that monitoring tools call to check the service is alive.
  • @app.get("/greet/{name}")A basic GET with a path parameter; name: str is matched to {name}.
  • @app.post("/echo")A POST endpoint. payload: dict is not a simple type, so FastAPI reads it from the JSON body.
💡
How decorators work

@app.get("/health") is the same as health = app.get("/health")(health). FastAPI stores (GET, "/health") → health(), inspects the parameters and type hints, and builds both the request parser and the documentation from them. One decorator per method: @app.get, @app.post, @app.put, @app.delete, @app.patch.

Type annotations — the foundation

from typing import Optional

def describe(tenure: int, label: Optional[str] = None) -> str:
    return f"tenure={tenure}, label={label}"

# Optional[str] means "a str or None". In Python 3.10+ you can also write: str | None

Plain Python ignores annotations at runtime — FastAPI and Pydantic read and enforce them. That single idea gives parsing, validation and documentation.

4 · Response models

class ScoreResponse(BaseModel):
    customer_id: Optional[str]
    risk_score: float


@app.post("/score", response_model=ScoreResponse)
def score(customer: Customer):
    # A simple rule-based score stands in for a real model in this demo.
    risk = 0.1 * customer.support_calls + customer.monthly_charges / 1000
    if customer.tenure < 6:
        risk += 0.3
    return {
        "customer_id": customer.customer_id,
        "risk_score": round(min(risk, 1.0), 3),
        "internal_note": "never sent to the client",  # removed by response_model
    }

response_model validates the output, drops extra keys (here internal_note) and documents the schema — protection against accidentally leaking internal fields.

Why validation matters in production ML

🤫 Silent failure

Models never complain about absurd inputs — they just return wrong answers.

📜 Clear contract

Client teams see exact fields, types and ranges in docs and errors.

🧯 Fewer 500s

Bad types become helpful 422s instead of stack traces deep in numpy.

🔐 Safer

Rejecting unknown fields and extreme values protects downstream systems.

def make_synthetic_dataset(n_samples: int = 2000, seed: int = RANDOM_SEED):
    """Create a reproducible synthetic churn dataset with three features."""
    rng = np.random.default_rng(seed)

    tenure = rng.integers(0, 73, size=n_samples)                 # months, 0-72
    monthly_charges = rng.uniform(20, 120, size=n_samples).round(2)
    support_calls = rng.poisson(lam=2.0, size=n_samples)         # 0, 1, 2, ...

    # Hidden "true" rule used to simulate churn behaviour:
    # short tenure, high charges and many support calls -> more likely to churn.
    logit = (
        -0.5
        - 0.07 * tenure
        + 0.03 * (monthly_charges - 70)
        + 0.65 * support_calls
    )
    churn_probability = 1 / (1 + np.exp(-logit))
    y = rng.binomial(n=1, p=churn_probability)

    # Column order MUST match FEATURE_NAMES.
    X = np.column_stack([tenure, monthly_charges, support_calls]).astype(float)
    return X, y


def main() -> None:
    X, y = make_synthetic_dataset()
    X_train, X_test, y_train, y_test = train_test_split(
        X, y, test_size=0.2, random_state=RANDOM_SEED, stratify=y
    )

    # Preprocessing + model in ONE object, so the API applies exactly the
    # same scaling that was used during training.
    pipeline = Pipeline(
        steps=[
            ("scaler", StandardScaler()),
            ("classifier", LogisticRegression(random_state=RANDOM_SEED)),
        ]
    )
    pipeline.fit(X_train, y_train)

    y_pred = pipeline.predict(X_test)
    accuracy = accuracy_score(y_test, y_pred)
    print(f"Test accuracy: {accuracy:.3f}")
    print(classification_report(y_test, y_pred, target_names=list(CLASS_LABELS.values())))

    # Save the pipeline together with the metadata the API needs.
    artifact = {
        "model": pipeline,
        "feature_names": FEATURE_NAMES,
        "class_labels": CLASS_LABELS,
        "model_version": MODEL_VERSION,
        "trained_at": datetime.now(timezone.utc).isoformat(),
        "test_accuracy": round(float(accuracy), 4),
    }
    MODEL_DIR.mkdir(parents=True, exist_ok=True)
    joblib.dump(artifact, MODEL_PATH)
    print(f"Model saved to: {MODEL_PATH}")

"""Request and response schemas for the churn prediction API."""
from typing import Optional

from pydantic import BaseModel, ConfigDict, Field


class ChurnFeatures(BaseModel):
    """Input features for one customer. Field names match training exactly."""

    model_config = ConfigDict(
        extra="forbid",  # reject unknown fields such as a misspelled "tenur"
        json_schema_extra={
            "examples": [
                {"tenure": 12, "monthly_charges": 85.5, "support_calls": 3}
            ]
        },
    )

    tenure: int = Field(..., ge=0, description="Months the customer has been subscribed")
    monthly_charges: float = Field(..., ge=0, description="Current monthly bill amount")
    support_calls: int = Field(..., ge=0, description="Support calls in the last 90 days")


class PredictionResponse(BaseModel):
    """Structured JSON returned by POST /predict."""

    # Allow field names that start with "model_" (Pydantic reserves that prefix).
    model_config = ConfigDict(protected_namespaces=())

    predicted_class: int = Field(..., description="0 = No Churn, 1 = Churn")
    label: str = Field(..., description="Human-readable class label")
    churn_probability: Optional[float] = Field(
        None, description="Probability of churn (class 1); null if the model has no predict_proba"
    )
    model_version: str


class HealthResponse(BaseModel):
    status: str
    model_loaded: bool
  • ChurnFeaturesField names identical to FEATURE_NAMES. ge=0 enforces non-negative values.
  • extra="forbid"Rejects unknown keys — catches typos like "tenur" that would otherwise be silently ignored.
  • json_schema_extraPre-fills the example request in Swagger UI.
  • PredictionResponseThe guaranteed output shape; churn_probability is Optional because not every classifier has predict_proba.
  • protected_namespaces=()Silences Pydantic's warning about field names starting with model_.

logger = logging.getLogger("churn_api")

PROJECT_ROOT = Path(__file__).resolve().parents[1]          # .../churn-api
MODEL_PATH = PROJECT_ROOT / "models" / "churn_model.joblib"  # same path as train.py
FEATURE_ORDER = ["tenure", "monthly_charges", "support_calls"]

# Holds the loaded artifact. Filled once at startup, read by every request.
ml_artifacts: dict[str, Any] = {}


@asynccontextmanager
async def lifespan(app: FastAPI):
    """Load the model ONCE when the server starts; clean up on shutdown."""
    try:
        artifact = joblib.load(MODEL_PATH)
        if artifact["feature_names"] != FEATURE_ORDER:
            raise ValueError(
                f"Feature mismatch: model expects {artifact['feature_names']}, "
                f"API sends {FEATURE_ORDER}"
            )
        ml_artifacts.update(artifact)
        logger.info("Model v%s loaded from %s", artifact["model_version"], MODEL_PATH)
    except FileNotFoundError:
        logger.error("Model file not found at %s. Run: python training/train.py", MODEL_PATH)
    except Exception:
        logger.exception("Failed to load model from %s", MODEL_PATH)
    yield
    ml_artifacts.clear()
    logger.info("Model unloaded, server shutting down")


app = FastAPI(
    title="Customer Churn Prediction API",
    description="Serves a scikit-learn churn model trained on synthetic data (for learning only).",
    version="1.0.0",
    lifespan=lifespan,
)


@app.get("/")
def root() -> dict:
    return {"message": "Customer Churn Prediction API. Open /docs to try it."}


@app.get("/health", response_model=HealthResponse)
def health() -> HealthResponse:
    """Liveness: the process is running and can answer HTTP requests."""
    return HealthResponse(status="ok", model_loaded="model" in ml_artifacts)


@app.get("/ready", response_model=HealthResponse)
def ready() -> HealthResponse:
    """Readiness: the service can actually make predictions."""
    if "model" not in ml_artifacts:
        raise HTTPException(
            status_code=status.HTTP_503_SERVICE_UNAVAILABLE,
            detail="Model not loaded",
        )
    return HealthResponse(status="ready", model_loaded=True)


@app.post("/predict", response_model=PredictionResponse)
def predict(features: ChurnFeatures) -> PredictionResponse:
    """Predict whether one customer will churn."""
    model = ml_artifacts.get("model")
    if model is None:
        raise HTTPException(
            status_code=status.HTTP_503_SERVICE_UNAVAILABLE,
            detail="Model is not loaded. Run 'python training/train.py' and restart the API.",
        )

    # Build a 2-D array (1 row x 3 columns) in the SAME order used in training.
    row = np.array([[getattr(features, name) for name in FEATURE_ORDER]], dtype=float)

    try:
        predicted_class = int(model.predict(row)[0])
        churn_probability = None
        if hasattr(model, "predict_proba"):
            class_index = list(model.classes_).index(1)        # column for "Churn"
            churn_probability = round(float(model.predict_proba(row)[0][class_index]), 4)
    except Exception:
        logger.exception("Prediction failed for input %s", features.model_dump())
        raise HTTPException(
            status_code=status.HTTP_500_INTERNAL_SERVER_ERROR,
            detail="Prediction failed due to an internal error.",
        )

    label = ml_artifacts["class_labels"][predicted_class]
    logger.info("input=%s prediction=%s prob=%s", features.model_dump(), label, churn_probability)

    return PredictionResponse(
        predicted_class=predicted_class,
        label=label,
        churn_probability=churn_probability,
        model_version=ml_artifacts["model_version"],
    )

API Quality and Error Handling

An API that "works on my laptop" is not finished. Quality means behaving predictably when things go wrong: bad input, missing model, unexpected exceptions, overloaded hosts.

Request validation errors

FastAPI turns every Pydantic failure into 422 with a detail list (type, loc, msg, input). Clients loop over detail to highlight the fields to fix — no code needed from you, as long as inputs are declared with types and Field constraints.

Meaningful HTTP status codes

Consistent response structures

✅ Success

Always the PredictionResponse shape — enforced by response_model.

⚠️ Errors

Always a detail key — a list for 422, a string for HTTPException.

🚫 Never

Return 200 with {"error": ...}. Clients and monitors rely on the code.

Optional pattern — a custom validation-error format

Some teams want a compact, uniform envelope. Add these imports and the handler to app/main.py after app = FastAPI(...):

from fastapi import Request

@app.exception_handler(RequestValidationError)

Why preprocessing must match training

🧨
Training–serving skew

Different scaling, different encoding or reordered columns at inference → the model still returns a number, it is just wrong, and nothing crashes. Our defences: preprocessing inside the saved Pipeline; one FEATURE_ORDER; a startup check against the artifact's feature_names; identical field names in the schema.

Why the model must not be loaded on every request

Read file+Unpickle×every request=slow + memory churn

Our toy model is tiny, but real models are often hundreds of MB and take seconds to load. Load once in lifespan, keep it in memory, reuse it.

About Infinity and NaN

Standard JSON has no Infinity or NaN, but Python's json module (and therefore requests) will happily send them. FEATURE_ORDER = ["tenure", "monthly_charges", "support_calls"]

# Holds the loaded artifact. Filled once at startup, read by every request.
ml_artifacts: dict[str, Any] = {}


@asynccontextmanager
async def lifespan(app: FastAPI):
    """Load the model ONCE when the server starts; clean up on shutdown."""
    try:
        artifact = joblib.load(MODEL_PATH)
        if artifact["feature_names"] != FEATURE_ORDER:
            raise ValueError(
                f"Feature mismatch: model expects {artifact['feature_names']}, "
                f"API sends {FEATURE_ORDER}"
            )
        ml_artifacts.update(artifact)
        logger.info("Model v%s loaded from %s", artifact["model_version"], MODEL_PATH)
    except FileNotFoundError:
        logger.error("Model file not found at %s. Run: python training/train.py", MODEL_PATH)
    except Exception:
        logger.exception("Failed to load model from %s", MODEL_PATH)
    yield
    ml_artifacts.clear()
    logger.info("Model unloaded, server shutting down")


app = FastAPI(
    title="Customer Churn Prediction API",
    description="Serves a scikit-learn churn model trained on synthetic data (for learning only).",
    version="1.0.0",
    lifespan=lifespan,
)

def root() -> dict:

🎤 Interview questions with model answers

1. Why put an ML model behind a REST API instead of shipping the model file to other teams?

An API decouples consumers from the model's language, libraries and hardware — clients only need HTTP and JSON. The ML team can retrain, change algorithms or scale infrastructure without touching clients, as long as the contract stays stable. It also centralises validation, logging, monitoring, access control and versioning, none of which is possible if every team embeds its own copy of a pickle file.

2. How does FastAPI validate request data, and what happens when validation fails?

FastAPI inspects the endpoint's type hints. Body parameters typed as Pydantic models are parsed and validated against field types and constraints (ge, le, max_length…). On failure the endpoint is not called; FastAPI returns 422 with a detail array giving each error's location, message, type and input. The same schemas generate the OpenAPI docs.

3. What is training–serving skew and how do you prevent it in a FastAPI service?

Any difference between how data is processed at training and at inference — scaling, encoding, feature order, defaults — which silently degrades predictions. Prevent it by saving preprocessing and model as one scikit-learn Pipeline, keeping a single feature list saved with the artifact and verified at startup, mirroring field names in the Pydantic schema, and testing API predictions against direct pipeline predictions on known samples.

4. Why load the model at startup, and why use def rather than async def for a scikit-learn endpoint?

Loading deserialises a potentially large file; per request it adds latency and memory churn. Loading once in lifespan keeps it in memory and lets a readiness probe report success. scikit-learn's predict is synchronous and CPU-bound; inside async def it would block the event loop for every other request. A plain def endpoint runs in FastAPI's thread pool, keeping the server responsive.

5. What is the difference between a liveness and a readiness probe for an ML service?

Liveness asks "is the process alive?" — on failure the orchestrator restarts the container, so it must be cheap and not depend on the model. Readiness asks "can it serve traffic now?" — it checks the model and other dependencies; on failure the instance is removed from the load balancer but not restarted. This lets slow-loading models warm up without being killed or receiving traffic too early.
